# LabMate：GitHub 相似项目与代码复用建议

核查日期：2026-10-25（北京时间）。共列出 17 个主要候选，另附不优先采用的项目。

本报告依据用户提供的交接文档、规格和 README，以及 GitHub 上的 README、源码目录、关键源文件、LICENSE 和仓库元数据。文档用于理解产品范围，其中的开发步骤不是本次执行任务。本次仅调研、保存报告，没有 fork、安装或运行第三方项目；功能判断不等于部署验收。最近推送指 GitHub `pushed_at`，不等于最近功能提交或维护质量。

## 结论

LabMate 已有 Vue 3 / TypeScript / FastAPI / SQLAlchemy 基础、模板版本、班级名单、离线双草稿和组内共享。当前更值得保留主体，吸收提交归档、报告导出和教师批阅的设计；计算图表在后续阶段接入。没有核实到一个同时满足 LabMate 全部业务规则的现成完成体。[项目 README](https://github.com/guifanhuayi/labmate-physics-assistant/blob/main/README.md)

优先阅读顺序：

1. **ExperimentalReportSystem**：最接近大学物理师生报告管理，但技术较老、部分实现待补齐。
2. **PhyX**：最值得研究的物理实验计算与 Word 报告 Web 应用，适合接受 AGPL 条件后的独立 fork。
3. **PhyPlot**：MIT + Vue 3 / TypeScript，最方便吸收数值表格、统计和拟合交互。
4. **eLabFTW**：重点研究实验记录、权限、修订和追溯；锁定机制不能直接等同 LabMate 的永久不可变提交。
5. **Physicallab**：现代 FastAPI 实验插件和 OCR 流程很贴近，但未找到项目许可证，先作为功能研究对象。

以下“移植难度、优先级、适配建议”是结合 LabMate 现状的工程判断。

## 一、直接面向物理实验的项目

### 1. ExperimentalReportSystem：大学物理实验报告系统

- 仓库：[NJAUzhangwenjun/ExperimentalReportSystem](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem)
- 技术：Java SSM、jQuery/Bootstrap、MySQL、Tomcat。
- 范围：有实际后端、页面、SQL 和实验处理类；包含学生实验录入/处理、报告提交与 Word 导出，以及教师成绩、学生管理。[README](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem/blob/master/README.md)
- 优先读：[提交与报告导出控制器](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem/blob/master/src/main/java/com/nanwulife/controller/backend/ExperimentSubmitController.java)、[教师成绩控制器](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem/blob/master/src/main/java/com/nanwulife/controller/backend/ScoreManageController.java)、[实验算法与报告模板](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem/tree/master/src/main/java/com/nanwulife/experimentRank)、[数据库结构](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem/blob/master/src/main/resources/reportSystem.sql)。
- 适配：优先参考师生业务、实验字段和报告模板；直接接入现有 FastAPI 的成本高。它比单个计算器更接近教学平台。
- 局限：关键控制器仍有 TODO；README 中的 MD5 密码设计不能替代 LabMate 现有 Argon2id。未核实具备“教师只能开启新尝试、旧提交永不改写”的规则。
- 授权：[Apache-2.0](https://github.com/NJAUzhangwenjun/ExperimentalReportSystem/blob/master/LICENSE)。最近推送：2022-12-16。[元数据](https://api.github.com/repos/NJAUzhangwenjun/ExperimentalReportSystem)

### 2. PhyX：物理实验数据处理与报告 Web 应用

- 仓库：[feixukeji/PhyX](https://github.com/feixukeji/PhyX)
- 技术：Flask、HTML/JS/Layui，NumPy、SciPy、pandas、SymPy、Matplotlib、python-docx 等。
- 范围：按实验上传 CSV/Excel，处理数据、拟合绘图、生成 Word；有不确定度计算、实验模块和 Word 公式转换。[README](https://github.com/feixukeji/PhyX/blob/main/README.md)
- 优先读：[计算函数](https://github.com/feixukeji/PhyX/blob/main/api/calc.py)、[Word 公式处理](https://github.com/feixukeji/PhyX/blob/main/api/insert.py)、[按实验拆分的模块](https://github.com/feixukeji/PhyX/tree/main/module)。
- 适配：可独立 fork 成为物理计算/报告子产品；也可在接受许可证条件后，将纯计算函数包装为 FastAPI 服务。适合 LabMate 后续计算、图表与报告阶段。
- 局限：不是完整班级/批阅平台；Web 入口有约五分钟后清理临时数据的逻辑，不能作为长期证据归档模型。[入口源码](https://github.com/feixukeji/PhyX/blob/main/main.py)
- 授权：[AGPL-3.0](https://github.com/feixukeji/PhyX/blob/main/LICENSE)。最近推送：2026-07-08。[元数据](https://api.github.com/repos/feixukeji/PhyX)

### 3. PhyPlot：Vue 物理数据表、统计与拟合

- 仓库：[Skrepy0/PhyPlot](https://github.com/Skrepy0/PhyPlot)
- 技术：Vue 3、Nuxt、TypeScript；Flask、NumPy、Matplotlib。
- 范围：单/双变量数据表、均值/方差/标准差，线性、指数等拟合和图表生成。[README](https://github.com/Skrepy0/PhyPlot/blob/main/README.md)
- 优先读：[DataTable.vue](https://github.com/Skrepy0/PhyPlot/blob/main/frontend/app/components/data-components/DataTable.vue)、[统计与拟合函数](https://github.com/Skrepy0/PhyPlot/tree/main/frontend/app/composables/math)、[绘图 API](https://github.com/Skrepy0/PhyPlot/blob/main/backend/src/app.py)。
- 适配：前端语言和 LabMate 接近，优先吸收录入与图表交互。Nuxt 组件仍需适配现有 Vite/Vue Router；权威计算应由后端重算。
- 局限：是分析应用，不是师生平台；单/双变量表不是任意复杂表头的实验模板设计器。
- 授权：[MIT](https://github.com/Skrepy0/PhyPlot/blob/main/LICENSE)。最近推送：2026-05-20。[元数据](https://api.github.com/repos/Skrepy0/PhyPlot)

### 4. PhysicsExp：轻量 Python 计算、绘图与 docx

- 仓库：[regymm/PhysicsExp](https://github.com/regymm/PhysicsExp)
- 范围：绘图封装、简单线性回归、文本数据读入、将图和文字组合为 Word。[README](https://github.com/regymm/PhysicsExp/blob/master/README.md)
- 优先读：[计算绘图函数](https://github.com/regymm/PhysicsExp/blob/master/physicsexp/mainfunc.py)、[docx 生成](https://github.com/regymm/PhysicsExp/blob/master/physicsexp/gendocx.py)。
- 适配：代码体量小，适合读取函数、做计算层原型；不是完整 Web 系统，也不是复杂报告设计器。
- 局限：JupyterHub 的 dummy authentication 示例不能当师生权限方案；数学边界和实验教学要求仍需自行验证。
- 授权：[MIT](https://github.com/regymm/PhysicsExp/blob/master/LICENSE)。最近推送：2022-03-16。[元数据](https://api.github.com/repos/regymm/PhysicsExp)

### 5. Physicallab：FastAPI 实验助手，高相似但许可缺失

- 仓库：[Bogger111/Physicallab](https://github.com/Bogger111/Physicallab)
- 技术：Next.js + FastAPI，实验配置/适配器，RapidOCR/PaddleOCR provider。
- 范围：README 介绍 12 个大学物理实验，流程为记录表上传、OCR 候选、人工核对、计算出图、Word/PDF。源码有统一实验接口、报告路由和 OCR 服务。[README](https://github.com/Bogger111/Physicallab/blob/master/README.md)
- 优先读：[实验接口](https://github.com/Bogger111/Physicallab/blob/master/backend/experiments/core/interfaces.py)、[报告路由](https://github.com/Bogger111/Physicallab/blob/master/backend/app/routers/reports.py)、[OCR provider](https://github.com/Bogger111/Physicallab/blob/master/backend/app/ocr_service.py)。
- 适配：重点研究实验插件接口、原始记录/OCR候选/确认值的分离。它与 LabMate 的文件提取证据模型很接近，但不等于已有师生提交、批阅和冻结流程。
- 授权：本次未找到项目 LICENSE；公开源码不能直接按 MIT/Apache 使用，复制实现前应取得明确许可。[递归文件树](https://api.github.com/repos/Bogger111/Physicallab/git/trees/master?recursive=1)
- 最近推送：2026-10-10。[元数据](https://api.github.com/repos/Bogger111/Physicallab)。README 的测试数量为作者声明，本次未复跑。

## 五、针对现有 LabMate 的吸收方案

| 当前需求 | 优先参考 | 建议落地边界 |
|---|---|---|
| 正式提交、历史尝试、附件与审计 | eLabFTW、nbgrader、ExperimentalReportSystem | 自建冻结提交和新尝试领域；这些项目提供流程参考，不能替代本项目的权限与并发约束 |
| Excel 与证据图片 | XlsxWriter 示例，保留现有 openpyxl | 导出只读快照；服务端生成平铺水印图片；记录 submission/attempt/template_version、文件哈希和生成版本 |
| 教师批阅、进度和原因码 | ExperimentalReportSystem、nbgrader、PrairieLearn | 批阅记录独立保存；复测创建新尝试，不改原始数据 |
| 公式和手机符号录入 | MathLive | 替换或增强输入体验，保留稳定字段 ID 与后端受控令牌模型 |
| 报告提取与人工核对 | Physicallab 的流程、PaddleOCR | 先处理现有 Excel/Word；OCR 后置，本地推理经验证后再启用；保留提取位置与候选，不混入学生原值 |
| 自动计算与图表 | PhyPlot、PhyX、PhysicsExp、lmfit | 以冻结数据为输入，计算结果独立存储，记录方法/版本/单位，不代替学生自行计算 |
| 异常与相似性 | 本次未找到可直接满足要求的现成模块 | 需结合实验误差、量纲、合法组共享设计规则；不能拿文本或代码查重器直接判定物理实验抄袭 |

优先完成阶段 5～6，再引入后期计算/OCR；不因发现新框架就重做已经实现的模板和离线草稿。

关于用户提到的“逆向开发”：本清单主要支持阅读公开实现、比较功能和独立重写。MIT/Apache/BSD 项目按各自许可证保留声明；AGPL 项目应按相应源码提供条件评估 fork/整合；LGPL 库按库的条款处理。无许可证的候选先取得授权再复制实现，不能通过改名、转写语言或包装 API 将其当作已授权代码。

## 核查边界

- 没有安装或运行第三方候选，没有测量浏览器性能、科学计算精度、漏洞或生产可用性。
- 没有把 README 的测试数量、识别准确率或性能宣传当作本次验证结果。
- 许可证按实际文件确认；PrairieLearn 和商业扩展按目录/版本分别看，不能只看仓库徽章。
- 后续真正选择某个项目时，应固定 commit/tag，再做启动验证、数据模型比对和最小实验样例验算。
