## 1. 文档原则

1. 本文区分三类内容：
   - **已实现**：当前 `main` 分支已有代码并通过相应测试或人工验收。
   - **已确认、待开发**：产品方案已确定，但仓库尚未实现或尚未完全实现。

3. 学生正式提交后数据立即冻结，学生和教师均不能修改；教师只能查看异常提示，系统重新分析须形成可追溯的新记录。

5. 当前不允许将匿名或非匿名学生数据发送给外部 AI 服务。

## 2. 产品概述

LabMate 面向大学物理实验教学，覆盖教师配置实验、发布任务、学生记录与提交数据、教师核验与批阅、证据留存和风险提示等流程。

试点规模已确认：

| 项目 | 规模 |
|---|---:|
| 学生 | 500 人 |
| 班级 | 16 个 |
| 教师 | 2 人 |
| 每名学生每年实验数 | 6 个 |

该规模不需要微服务。模块化单体、关系数据库和对象存储足以支持试点，并能在后期平滑迁移到学校服务器。

### 2.1 角色

- **学生**：首次使用姓名和学号设置密码并绑定手机号、查看实验、录入或上传数据、正式提交、查看教师反馈。
- **教师**：管理班级与名单、设计实验模板、发布任务、设置组内共享、查看明显异常的数据、批阅及要求修改或复测，但不能修改学生数据。
- **管理员**：账号与教师范围管理、系统配置、审计和运维。

### 2.2 当前优先级

1. 完善阶段 0～3 已完成能力与产品决策之间的差异。
2. 完成学生动态数据录入、自动保存和正式提交。
3. 完成不可变提交、历史实验尝试、证据链、水印图片和 Excel 导出。
4. 再完成教师批阅、异常提示和相似性风险提示。
5. 自动计算与图表从原阶段 5 延后，不阻塞数据提交、水印和 Excel 主流程。

### 2.3 学生端设备与页面尺寸（2026-10-27 确认）

学生主要使用**手机和平板**填写，学生端必须以移动设备为布局和验收基准，不能按桌面工作台的固定宽度制作后整体缩放。电脑浏览作为兼容入口，不替代手机、平板验收；教师和管理员工作台可继续采用桌面布局。

- 覆盖学生登录/首次设置、任务列表、实验操作与动态录入、同步状态、冲突处理，以及后续提交、附件和反馈页面。
- 采用流式单栏页面、可换行的标题/状态/操作区、适合触控的控件；页面不得出现整体横向溢出。不得禁用浏览器缩放。
- 宽数据表保留模板行列、合并单元格、符号、单位、字段绑定和共享属性，仅在表格区域横向滑动，并提供可见提示；不能裁掉测量项或缩小整页来塞入表格。
- 手机与平板数字录入使用屏幕底部数字键盘，按键至少 44 CSS px 高，输入框字体不小于 16 CSS px；当前字段与数值保持可见，适配安全区与横屏。宽度变化或旋转后立即更新，无需刷新。
- 以 CSS 视口验收：320×568、390×844、844×390、768×1024、1024×768、820×1180、1180×820；触屏平板横屏即使超过 1024 px 仍须可用。桌面兼容另查 1440×900。断点是布局策略，不是固定画布尺寸。
- 布局修改不得改变草稿键、模板 ID/版本、API、格式校验、IndexedDB/服务端自动保存、离线恢复、共享授权、冲突合并或只读限制。旋转与尺寸变化不清空输入、不重新加载任务。
- 开发须包含浏览器视口回归；真实手机/平板上的系统键盘、旋转、安全区和触控体验须补充人工验收。浏览器模拟通过不等于真实设备验收完成。

本次实现与检查清单见 `学生端手机与平板适配规范_2026-10-27.md`。后续学生端功能必须沿用本节约束。

### 2.4 管理员后台设计与技术接入（2026-10-27 确认）

管理员后台统一使用 **Ant Design Pro 设计体系及官方 ProComponents**，以侧边导航、页头、面包屑、概览卡片、查询表格、表单、抽屉和确认弹窗组织后台操作。后续管理员页面沿用该体系，不继续将管理员业务堆叠到教师准备工作台。

- 项目主应用继续使用 Vue 3。`/admin` 为管理员独立页面，按需加载 React/React DOM 与官方 ProLayout、PageContainer、ProTable、ProForm、Ant Design；使用独立挂载边界集成，不将整个师生系统改为 React，也不引入整套 Umi 脚手架。不能把手写 CSS 仿制界面称为已接入官方组件。
- 本次复用当前班级、教师目录与名单 API，保留指定负责教师创建班级、查看学生、名单先预览后确认导入、删除班级确认和退出登录。教师目录为只读，账号编辑/停用、审计等尚无对应实现时不得显示为已交付。
- 维持现有 HttpOnly 会话、Vue 路由角色守卫与服务端资源权限。管理员页面不生成新权限体系，不以菜单隐藏替代服务端授权，不授予管理员修改冻结学生提交的能力。
- React 根节点、CSS-in-JS 样式和弹窗容器隔离到管理员 Shadow DOM；离开页面清理 React 根节点。管理员依赖不得在学生/教师入口预先加载，不能污染学生手机/平板布局、教师模板和 Univer 样式。
- 固定依赖 ProComponents 2.8.10 / Ant Design 5.29.3，沿用 React 19.3.1，配置 React 19 兼容包与 TypeScript 类型。升级先核验 peerDependencies，再验收管理员、教师和学生三种入口。
- 验收包括管理员导航与刷新、原班级/名单工作流、失败提示和删除确认、非管理员访问拦截、依赖按需加载、样式隔离，以及学生移动端回归。不得用示例统计值或虚构 API 代替真实业务数据。

实现与验收入口见 `管理员后台AntDesignPro接入说明_2026-10-27.md`、README 和 `pnpm e2e:admin`。

### 4.2 分工原则

**前端负责：**

- 模板和表格的可视化编辑；
- 学生移动端录入体验、本地 IndexedDB 暂存、离线提示；
- 符号面板、公式令牌编辑器、数值键盘和错误定位；
- 提交状态、历史尝试和风险证据的展示；
- 不将前端校验当作最终权限或业务判定。

**后端负责：**

- 登录、首次设密、手机号绑定与验证、会话、角色与资源级权限；
- 班级、分组、模板版本、任务、共享数据、实验尝试和不可变提交；
- 表格结构、字段、公式、异常和相似性规则的最终校验；
- 学生提交值、文件提取值和计算值的分别存储；
- 水印生成、Excel 导出、文件摘要、审计和保留/删除策略。

### 4.3 当前分工存在的问题与调整

1. **登录策略与已确认产品决策不一致。** 当前真实模式包含连续失败后的账号限流，且测试使用预设密码。应改为首次用“姓名 + 学号”匹配名单、设置密码并绑定经短信验证的手机号，不需要教师发放激活码；学生账号不因多次输错密码而被锁定。仍可按 IP、设备和接口实施短时限速、渐进延迟、告警与验证码，防止暴力破解，但不得造成学生账号级锁定。
2. **字段显示符号与机器标识仍需彻底分离。** `field_id/key` 必须稳定且只供系统引用；名称、字母、上下标和单位仅用于展示。教师改 `U` 为 `U₁` 时不能破坏公式或历史数据。
3. **学生提交领域尚未建立。** 下一阶段需要新增草稿、不可变提交、实验尝试、附件、提取证据和审计模型，不能继续只依赖前端状态。
4. **组内共享需要独立领域模型。** 应新增实验分组、组员、共享数据集和共享权限，避免通过复制学生数据临时实现。
5. **教师不能修改学生值。** 异常规则只向教师提供观察值、阈值和证据；教师可添加批阅意见或要求新一次修改/复测，但不能改写已提交数据。
6. **报告提取值不能与学生填写值混为一项。** 教师端同时展示学生填写的结果、从上传文件提取的原始结果及差异。
7. **前端管理页和 API 客户端已开始变大。** 进入阶段 4 后按 `auth/classes/templates/assignments/submissions/reviews` 拆分模块，避免所有教师功能继续堆在一个页面和一个客户端文件中。

## 5. 核心领域模型

### 5.1 已有模型

- `User`：用户、学号/工号、角色、密码摘要、状态。
- `AuthSession`：服务端会话。
- `AuditLog`：登录和关键业务审计。

### 5.2 下一阶段新增模型

- `StudentEnrollment`：首次设密状态、姓名/学号名单匹配、绑定手机号和验证时间。

- `SharedDataset`、`SharedDataRevision`：教师允许后同组共享的原始实验数据及版本。
- `SubmissionDraft`：学生服务端草稿及版本号。
- `SubmissionAttempt`、`Submission`：教师允许的实验尝试及每次尝试中不可变的正式提交。

- `AnomalyFinding`、`SimilarityFinding`：可解释的规则命中证据。

## 6. 登录、账号与安全策略

### 6.1 学生首次登录

已确认规则：系统不设置统一初始密码，也不要求教师发放激活码。学生首次登录时输入姓名和完整学号，系统与已导入名单精确匹配；匹配后由学生设置密码，并绑定手机号。

推荐流程：

1. 学生输入姓名和完整学号；
2. 系统与名单中的姓名、学号组合精确匹配，并确认账号尚未完成首次设置；
3. 学生设置个人密码并再次确认；
4. 学生填写手机号，通过短信验证码确认手机号归属；该短信验证码只用于验证手机号，不是教师预先发放的账号激活码；
5. 系统完成手机号绑定并记录首次设置时间、来源 IP 和审计事件；
6. 后续登录允许使用学号或已绑定手机号加密码。

“姓名 + 学号”可能被同学或名单接触者获知，因此首次设置接口必须限制单个 IP/设备的批量尝试，姓名匹配失败时使用统一错误提示，并向已经绑定的手机号发送首次设置通知。账号被他人抢先设置时，由教师核验身份后发起手机号和密码重置。

### 6.2 登录失败处理

- 学生多次输错密码后**不锁定账号**，不设置“等待 15 分钟才能再次登录”的账号级策略。
- 可保留 IP/设备/接口级速率限制、渐进延迟、异常告警和高风险时的人机验证。
- 错误提示不暴露“学号是否存在”或“账号是否已完成首次设置”。
- 教师和管理员可采用更强的多因素认证；其安全策略不受“学生账号不锁定”限制。
- 密码使用 Argon2id 等适合密码的摘要算法，明文密码不得落库、落日志或进入前端长期存储。

### 6.3 权限原则

- 教师只能管理自己负责的班级、任务和学生数据；管理员授权必须审计。
- 学生只能访问自己的数据，以及教师明确开启的本实验同组共享数据。
- 对象存储文件为私有，使用短时签名 URL；不得使用可枚举公开链接。

## 7. 班级与学生名单导入

### 7.1 文件格式

学生名单导入不要求、也不展示“班级代码”。教师必须先在工作台选择目标班级，再上传名单。

导入模板只要求以下两列：

| 列名 | 必填 | 规则 |
|---|---|---|
| 学号 | 是 | 按文本读取，保留前导零，去除首尾空格 |
| 姓名 | 是 | 非空，保留合法中文、字母和常用分隔符 |

班级归属由教师上传前选择的目标班级决定。班级名称、学期和内部 ID 从目标班级读取，不要求在每一行重复。系统内部可以保留不可见的班级 UUID；这不等于要求教师或名单提供班级代码。

若旧文件包含“班级代码”列，新版本导入器应忽略该列并给出非阻断提示，不再因代码缺失或不一致阻止导入。

### 7.2 预览与提交

1. 解析 xlsx/csv，统一表头和空白字符；
2. 显示总行数、可导入行、错误行和重复行；
3. 校验学号、姓名、文件内重复、系统内冲突；
4. 教师确认后使用单一数据库事务写入；
5. 任一阻断错误不得产生半导入账号或成员；
6. 导入完成后立即显示学生列表；
7. 可下载错误行和原因。

## 8. 实验模板与任务发布

### 8.1 模板结构

模板由以下部分组成：

- 实验名称、目标、预习问题和讨论问题；
- 操作步骤及其关联的数据表；
- 一张或多张数据记录表；
- 字段定义、输入约束和共享属性；
- 最低提交要求；
- 可选的公式和图表定义（计算执行与图表生成延后）；
- 文件上传要求、截止时间与提交后冻结规则。

### 8.2 模板设计器页面

模板设计器采用“表格结构 + 字段定义 + 学生端预览”三栏或分步布局，使教师不需要编辑 JSON。

#### A. 表格结构编辑

- 新增、复制、删除和重命名数据表；
- 自定义总行数、总列数和数据起始行；
- 通过按钮增加/删除行列，也可直接输入目标行列数；
- 拖拽选择矩形区域；
- 合并表头或说明单元格；
- 拆分已合并单元格；
- 数据录入单元格默认不允许跨字段合并，避免无法确定保存位置；
- 设置单元格文本、对齐、只读、说明和字段绑定；
- 调整列宽、冻结表头，并实时预览手机端横向滚动或卡片式布局；
- 删除行列、拆分或改绑字段时显示影响范围并支持撤销。

#### B. 数据字段设计

每个需要学生记录的数据均为独立字段，教师可配置：

| 属性 | 示例 | 说明 |
|---|---|---|
| 稳定字段 ID | `voltage_1` | 系统生成或校验，发布后不可变 |
| 数据名称 | 电压 | 面向师生显示 |
| 符号 | `U₁` | 支持希腊字母、上下标和常用物理符号 |
| 类型 | 数值、整数、文本、枚举、时间、图片 | 决定输入控件和校验方式 |
| 单位 | V | 与数值分开保存 |
| 精度/有效数字 | 0.01 或 3 位有效数字 | 用于显示、异常容差和导出 |
| 合理范围 | 0～12 | 为提示规则，不自动判定实验失败 |
| 必填 | 是/否 | 提交前校验 |
| 数据归属 | 个人/同组共享 | 仅教师可设置 |
| 说明 | 读数稳定后记录 | 学生端提示 |

字段绑定后，表格单元格只保存对字段 ID 的引用。字段名称或符号变化不改变历史数据和公式依赖。

#### C. 发布与版本

- 草稿可反复保存；
- 发布前由后端检查表格边界、重叠、空洞、非法绑定、重复字段 ID 和无效依赖；
- 发布生成不可变 `TemplateVersion`；
- 后续编辑产生新草稿和新版本，不修改已发布任务使用的旧版本；
- 任务发布时固定模板版本、班级、起止时间、共享规则和提交规则。

### 8.3 当前实现与待增强

当前已经实现数据表增减、行列调整、矩形选区、表头合并/拆分、字段绑定、名称/类型/符号/单位/精度/上下限/必填配置、服务端结构校验和不可变版本发布。

待增强项：列宽和冻结、撤销/重做、公式令牌编辑器、符号快捷面板、组内共享字段标记、手机端真实录入预览及无障碍操作。

## 9. 公式、字母与物理符号的录入方案

### 9.1 核心设计

教师和学生不应依赖系统键盘直接输入复杂希腊字母、上下标或公式。系统采用“语义字段 + 可视化令牌公式”的方式：

- `fieldId`：稳定机器标识，如 `voltage_1`；
- `label`：中文名称，如“第一次电压”；
- `symbol`：显示符号，如 `U₁`；
- `unit`：单位，如 `V`；
- 公式内部引用字段 ID，界面按符号显示。

### 9.2 教师端公式编辑器

公式区由以下控件组成：

1. **变量面板**：自动列出已定义字段，显示“电压 U₁ / V”，点击插入；
2. **运算面板**：`+`、`−`、`×`、`÷`、括号、幂、根号、绝对值、平均值等白名单运算；
3. **符号面板**：希腊字母、Δ、Ω、θ、λ、μ、π、上下标 0～9、平方/立方和常用物理常量；
4. **搜索和收藏**：输入“欧姆”“delta”“下标 1”即可找到符号；
5. **快捷输入**：可选支持 `\alpha`、`Delta`、`_1`、`^2` 转换，但不要求教师记忆；
6. **即时预览**：同时展示数学排版和可读文本，如“电阻 = 电压 ÷ 电流”；
7. **即时校验**：未知变量、量纲明显不一致、除零风险和循环依赖在发布前提示。

公式保存为受控语法树或令牌列表，不保存任意可执行代码，也不使用 `eval`。

### 9.3 学生端录入

- 普通实验数据格只输入数值，不要求学生再次键入 `U`、`I`、`Δx` 等符号；符号和单位固定显示在字段标题旁。
- 结果项使用“名称 + 符号 + 单位 + 数值框”，学生只填写数值和必要的有效数字。
- 若确需学生填写表达式，使用与教师端相同的变量令牌和运算键盘；点击变量即可插入，不依赖手机系统键盘。
- 手机和平板的数值格使用屏幕底部数字键盘，显示当前字段与数值，不挤占表格单元格；预留安全区并避免遮挡当前输入。复杂表达式的常用符号栏、撤销、删除令牌和语音阅读标签属于待开发能力，不因本次布局调整视为已实现。
- 导出和无障碍文本同时保留符号形式与纯文本说明，避免字体缺失造成信息丢失。

## 10. 同组数据共享

教师可以针对某一个实验任务开启或关闭同组学生共享实验数据。

- 共享权限是任务级配置，不是班级永久设置；
- 教师创建分组并确定成员，变更成员需审计；
- 共享的数据字段由模板明确标记；个人结论、计算过程和报告文字默认不共享；
- 共享原始数据形成独立 `SharedDataset`，记录录入者和每次修订；
- 同组成员看到共享值的来源和最后更新时间；
- 提交后共享版本锁定，后续更改形成新版本；
- 相似性分析必须排除同组被允许共享的数据，只分析个人字段或未经授权的跨组相同数据。

## 11. 学生数据录入、自动保存与提交

### 11.1 自动保存

- 前端变更先写入 IndexedDB，再异步同步到服务器草稿；
- 服务端以乐观版本号处理冲突，不使用最后写入静默覆盖；
- 页面显示“本地已保存 / 已同步 / 同步失败 / 存在冲突”；
- 断网恢复后按字段级差异提示合并；
- 敏感信息不写入 `localStorage`。

### 11.2 正式提交与冻结

已确认规则：学生点击正式提交并再次确认后，该次实验的数据和附件立即冻结，学生不能撤回、修改、替换文件或自行重新上传，教师也不能修改其中的任何数据。

具体规则：

1. 正式提交创建不可变 `Submission`，冻结当时的表格、文件、模板版本和摘要；
2. 提交确认框明确告知“提交后无法修改”，并在提交前完成必填项和文件完整性检查；
3. 页面不提供撤回、覆盖、重新上传或修改入口；
4. 每次提交记录服务器提交时间、来源、附件哈希、水印产物和分析版本；
5. 教师只能查看、批阅、标记异常和作出审核决定，不能改动提交内容；
6. 若教师要求修改或复测，由教师创建一个新的实验尝试，学生在新尝试中重新填写并提交；原提交永久保持不变；
7. 新尝试是独立记录，不能复用旧文件地址或覆盖旧提交，并必须关联触发它的教师决定。

### 11.3 报告计算结果

- 实验报告的计算由学生自行完成并填写结果；
- 系统不以自动计算代替学生计算；
- 对上传的 Word、Excel、图片或 PDF，可在本地/服务器受控环境提取其中的原始计算结果；
- 教师端并列展示“学生填写结果”“文件提取结果”“差值/一致性提示”；
- 提取失败或置信度低时必须标记，不得猜测或自动回写学生结果；
- 自动计算和图表的完整功能延后，但可保留最小的格式、必填和范围校验。

## 12. 教师查看异常数据

教师不可以修正、覆盖或替换学生提交的异常数据，只可以查看系统标记的明显异常值及其判定证据。

查看与处理流程：

1. 教师从任务概览进入异常列表，可按学生、字段、规则和严重程度筛选；
2. 教师查看观察值、阈值、同条件基线、文件提取结果和规则说明；
3. 教师可以把提示标记为“已查看、需说明、疑似测量错误、规则误报”，并填写批阅意见；
4. 任何标记和意见都不改变学生提交值；
5. 需要学生处理时，教师作出“需修改/复测”决定并创建新的实验尝试；
6. 原提交、原异常提示和教师意见始终保留；
7. 导出只呈现学生实际提交的数据，并可附异常提示，不生成所谓“教师修正值”或“最终采用值”。

## 13. 异常规则判定

异常规则只用于提示和核验，不能自动认定学生错误、作弊或实验不合格。

### 13.1 分层规则

| 层级 | 规则 | 示例 |
|---|---|---|
| A. 硬校验 | 缺失、类型、单位、行数、不可解析 | 必填电压为空；文本填入数值字段 |
| B. 单份数据一致性 | 重复测量离散度、单调性、跳变、分辨率、残差 | 同条件 5 次测量变异系数过大 |
| C. 同任务稳健统计 | 中位数/MAD、IQR、分位数 | 与同模板、同仪器条件的样本差异明显 |
| D. 物理约束 | 符号、范围、趋势、守恒或模型残差 | 理论上应为正值却出现负值 |
| E. 交叉证据 | 填写值、文件提取值、共享值和教师确认值对比 | 报告中的结果与页面填写值不一致 |

### 13.2 判定原则

- 同行比较必须限定同一任务、模板版本、仪器量程和实验条件；
- 小样本不得使用不稳定的均值/标准差阈值，优先中位数、MAD 和 IQR；样本不足时只显示“无法形成群体基线”；
- 容差结合仪器分辨率、字段精度和实验条件，不能全系统使用固定百分比；
- 阈值采用“系统默认 → 模板 → 任务”三级继承，发布时版本化；
- 规则调整不静默改变历史结论，重新分析时产生新分析版本；
- 单个规则命中只生成低或中级提示，严重提示需多项独立证据或明确物理不可能条件；
- 教师可将提示标记为有效、误报或无需处理，用于后续校准，但不自动训练外部模型。

### 13.3 输出证据

每条异常提示至少包含：规则名称和版本、观察值、阈值、基线样本数、所属条件、严重程度、可读解释和建议核验动作。界面用“提示”“需核验”表述，不使用“作弊”“造假”等结论性措辞。

## 14. 水印、证据与导出

### 14.1 水印版式

水印改为斜向长串文字，在整个页面或图片范围内重复铺满，防止通过裁剪去除角落水印。

推荐水印字符串：

`姓名｜学号｜实验名称｜服务器提交时间`

已确认允许在水印图片中出现完整学号。

水印可见内容仅包含以上四项，不加入产品名称、报告编号、提交版本、摘要短码或其他文字。用于完整性校验的提交 ID、哈希和生成器版本只保存在服务端元数据中，不显示在水印正文内。

版式要求：

- 旋转角约 `-25°`～`-35°`；
- 横纵重复平铺并错列，覆盖内容区、空白区和页边距；
- 低透明度但在浅色和深色区域均可识别；
- 可使用两层不同间距/透明度水印，降低简单修复难度；
- 由服务端合成到最终像素或 PDF 内容中，不能只用可删除的 CSS 覆盖层；
- 每个常见裁剪区域内尽量至少保留一段姓名、学号、实验名称或服务器提交时间；
- 不以水印宣称绝对防篡改，水印负责溯源，哈希和审计负责完整性证明。

### 14.2 证据链

- 原始上传文件、标准化预览、水印版产物分别保存并计算 SHA-256；
- 数据库记录模板版本、实验尝试、提交 ID、服务器时间、生成器版本和文件哈希；
- 教师授权范围内可查看非水印原件，用于争议核验。

### 14.3 Excel 导出

阶段 5 优先完成 Excel，而不是优先完成图表：

- 按实验模板生成工作簿，保留表头合并、行列结构、字段名称、符号和单位；
- 明确区分学生提交值、合法共享值和文件提取证据，不提供教师修改值；
- 附带实验尝试、模板版本、时间、学生/小组和哈希摘要；
- 公式单元格初期可以导出学生填写结果及来源说明，复杂自动公式延后；
- 导出在后端异步生成，使用短时签名下载链接并记录审计；
- 防止公式注入：以 `= + - @` 开头的文本必须转义，不能当作工作簿公式执行。

## 15. 相似性与抄袭风险预警

风险预警用于帮助教师定位值得复核的提交，不直接作出学术不端结论。

### 15.1 比较范围

- 只比较同一实验任务、模板版本和可比实验条件；
- 数据分为公共常量、教师预置值、同组合法共享值、个人观测值、派生结果和报告文本；
- 公共常量、教师预置值和同组合法共享值不计入同组抄袭风险；
- 同组成员的个人字段、计算结果和文字仍可比较；
- 未授权的跨组共享块可以成为风险证据。

### 15.2 多信号方法

1. 归一化后的整段数值序列完全相同；
2. 基于仪器分辨率的逐列容差匹配率；
3. 行对齐/编辑距离，识别增删少量行后的复制；
4. 罕见异常值、缺失位置和离群点位置共同出现；
5. 小数末位和舍入模式过度一致；
6. 对一组数据施加统一比例、偏移或简单变换后高度重合；
7. 模型残差“指纹”相似，而不仅仅是相关系数高；
8. 附件文件哈希、图片感知哈希及元数据相似；
9. 提交时间只作为弱证据，不单独触发高风险。

不能把高相关系数直接视为抄袭，因为同一物理规律下正常数据也可能高度相关。高风险至少需要两类相互独立的强证据；只有单项证据时最多标为“建议查看”。

### 15.3 输出与校准

- 输出风险等级、命中的信号、排除的共享字段、可视化差异和算法版本；
- 教师可以标记“确认相似、合理共享、误报、证据不足”；
- 上线前使用脱敏测试集评估误报率，重点检查同组共享和相同仪器分辨率造成的误报；
- 不将风险分数作为自动扣分、自动退回或纪律处分依据；
- 当前使用本地确定性算法，不向外部 AI 发送匿名或非匿名数据。

## 16. 教师批阅状态

“退回修改”和“要求复测”使用同一个主状态 `revision_required`，通过原因码区分：

- `edit_required`：数据、填写、附件或说明需要修改；
- `retest_required`：需要重新进行部分或全部实验。

教师反馈必须说明原因、涉及字段/附件和新实验尝试的截止时间。学生只能在教师创建的新尝试中重新填写，原提交和原反馈永久保留到实验删除流程执行。

建议状态流转：

`draft → submitted → under_review → accepted`  
`under_review → revision_required → new_attempt_open → submitted → under_review`

学生提交后不能自行回到 `draft`、撤回、修改或重新上传。只有教师作出“需修改/复测”决定后，系统才创建独立的新实验尝试；旧提交仍保持冻结。

## 17. 数据保留与实验删除

已确认：教师删除实验后，学生历史数据和图片进入固定 30 天缓冲期；缓冲期内可以恢复，期满后再执行永久清理。

为避免误删和备份泄漏，删除采用两阶段：

1. 教师删除实验时先软删除，前台不可见并进入固定 30 天恢复期；
2. 恢复期结束后由后台任务清理数据库明细、对象存储文件、导出物和派生预览；
3. 审计日志保留最少必要事件，不保留无必要的实验内容；
4. 备份按既定周期自然过期，不从历史备份中逐条修改；
5. 若学校档案制度或争议处理要求更长保留期，管理员可设置合法保留锁并记录原因；
6. 删除前显示影响范围和预计永久清除日期。

## 18. API 与并发约定

- API 使用 `/api` 前缀和结构化错误：`code`、`message`、`field/path`、`details`。
- 修改草稿、共享数据和提交使用版本号或 ETag，冲突返回 `409`。
- 文件上传采用大小、类型、扩展名与内容签名联合校验；Office/PDF/图片解析放入隔离的后台任务。
- 耗时任务（导出、水印、文件提取、相似性分析）返回任务 ID，前端轮询或订阅状态。
- 所有关键写操作携带请求 ID，支持幂等提交，避免网络重试产生重复版本。
- 时间统一按 UTC 存储，界面按 Asia/Shanghai 显示。

## 19. 部署形态

### 19.1 试点部署

试点阶段部署到中国大陆阿里云服务器，推荐：

- 一台适当规格的 ECS 运行 Nginx、Vue 静态资源、FastAPI API 和后台任务；
- PostgreSQL 优先使用阿里云 RDS；预算有限时可先同机运行，但必须做自动化异机/对象存储备份和恢复演练；
- 学生图片、报告、水印和 Excel 放入私有 OSS，开启版本控制/生命周期；
- Redis 初期可选，仅在后台任务队列、缓存或限速确有需要时加入；
- 全站 HTTPS、最小权限安全组、数据库不暴露公网、日志与告警分离；
- 不拆微服务，避免增加试点运维复杂度。

相比“所有内容只放一台服务器磁盘”，上述方案把大文件放到 OSS，并让数据库具备独立备份或托管能力，风险更低且便于迁移。

### 19.2 后期学校服务器

- 保持 Docker 镜像、环境变量和数据库迁移脚本可移植；
- 使用 PostgreSQL 逻辑备份/恢复迁移业务数据；
- 从 OSS 导出对象及清单，迁入学校对象存储或文件服务；
- 域名、Cookie、CORS、签名 URL 和密钥通过环境配置切换；
- 迁移前进行校验和比对、停机窗口和回滚演练。

### 19.3 备案建议

结论：如果在中国大陆阿里云以公网域名向师生提供服务，即使只是 500 人小范围、免费试点，也不应把“小范围”视为免备案理由。建议在公开试用前完成非经营性互联网信息服务备案；若未来收费或具有经营性质，再评估相应许可。教育类信息服务是否需要主管部门前置审批，应在提交备案前向服务器所在地通信管理局、阿里云备案顾问及学校主管部门确认。

暂不使用学校子域名可行，但应使用由实际主办单位依法持有和备案的独立域名，不建议用裸 IP 对真实学生开放。上线后还应按属地公安机关要求及时完成公安联网备案，实践上按网站正式联网后 30 日内办理准备。

若备案办理期间必须先做产品验证，只能在本地、校园内网、VPN 或严格访问控制的非公开环境使用测试/脱敏数据；不建议在未备案的大陆公网服务中先放入 500 名真实学生信息。

### 19.4 上线前安全审查

安全审查为真实学生试点的上线门槛。至少完成：

- 身份、对象级越权和教师数据范围测试；
- 上传文件类型欺骗、恶意文档、路径穿越和公式注入测试；
- SQL 注入、XSS、CSRF、会话固定和 Cookie 配置检查；
- 依赖、容器镜像和密钥泄漏扫描；
- OSS 私有权限、签名 URL 和备份恢复演练；
- 日志脱敏、个人信息告知、最小收集和删除流程检查；
- 容量、并发、失败恢复和告警演练。

是否以及如何开展网络安全等级保护，应由主办单位结合系统实际定级，并与学校信息化/网络安全部门及属地主管机构确认。本文不擅自指定等级。

- 正式提交后冻结，学生和教师均不能修改、撤回或自行重新上传；
- 保存不可变提交、教师发起的新实验尝试、文件、哈希和审计；
- 服务端生成斜向长串、全页平铺水印；
- Excel 导出与公式注入防护；
- 教师查看学生填写结果和文件提取原始结果；
- 暂不以完整自动计算和图表作为本阶段验收前置条件。

### 阶段 6：教师核验与批阅

- 教师进度面板和历史实验尝试对比；
- 明显异常数据列表、证据查看和批阅标记，不提供教师修改入口；
- 通过、需修改/复测及原因码；
- 教师创建新实验尝试的闭环，原提交保持冻结。

### 阶段 7：自动计算与图表——延后

- 白名单计算执行器；
- 量纲、依赖和除零检查；
- 趋势图、拟合和图表导出；
- 始终与学生自行填写的结果并列，不代替学生计算。

### 阶段 8：异常与相似性风险

- 分层异常规则、稳健统计和证据说明；
- 排除合法同组共享的多信号相似性分析；
- 教师复核和误报反馈；
- 不自动作出处分或成绩决定。

### 阶段 9：AI 辅助——暂不启用外部服务

- 当前不向外部 AI 发送任何学生数据，包括匿名数据；
- 若未来启用，必须另行完成产品确认、隐私影响评估、数据边界和学校审批；
- 未审批前仅使用本地确定性解析和规则。

### 阶段 10：试点部署与迁移准备

- 阿里云部署、备案、HTTPS、备份与监控；
- 安全审查和容量演练；
- 500 学生、16 班、2 教师、每年 6 个实验试点；
- 保持向学校服务器迁移的容器、数据库和对象清单能力。

## 21. 测试策略

### 21.1 必须保留的自动测试

- 后端权限矩阵、事务导入、模板版本与结构校验；
- 姓名/学号首次设置、手机号绑定、重复设置、弱密码、会话和不锁号策略；
- 草稿并发冲突、正式提交幂等、提交后禁止修改；
- 教师异常查看权限以及无法修改学生值的反向授权测试；
- 水印内容、位置覆盖、哈希和导出追溯；
- Excel 结构、类型和公式注入防护；
- 合法组内共享的相似性排除；
- 删除恢复期和后台清理。

### 21.2 端到端主流程

1. 教师创建班级并导入只有“学号、姓名”的名单；
2. 学生用姓名和学号首次设置密码、绑定手机号，并使用学号或手机号登录；
3. 教师设计含合并表头、符号和共享字段的实验模板并发布；
4. 学生断网/联网录入，同组查看合法共享数据；
5. 学生提交后无法撤回、修改或自行重新上传；
6. 系统生成全页斜向水印和 Excel；
7. 教师对比学生结果与文件提取结果并查看异常证据，但不能修改数值；
8. 教师要求修改或复测并创建新实验尝试，原提交保持冻结；
9. 相似性分析排除合法共享数据并显示可解释证据。

## 22. 阶段 0～5 验收标准

### 阶段 0～3

- `main` 分支 CI 全绿；
- 班级、名单、模板和任务均使用真实后端数据；
- 名单文件无需班级代码；
- 模板表格可改行列、合并/拆分和配置字段名称、类型、符号、单位；
- 公式和符号无需依赖复杂系统键盘；
- 发布版本不可变且任务固定引用版本。

### 阶段 4

- 学生可在手机和平板的横竖屏按模板录入，以第 2.3 节尺寸矩阵验收；电脑只作为兼容入口；
- 页面无整体横向溢出；宽表格只在局部滚动，触控键盘与同步/冲突操作可达；旋转不丢失已填数据；
- 断网不丢失，联网可同步；
- 冲突不会静默覆盖；
- 组内共享只能在教师开启、限定字段和限定成员时发生。

### 阶段 5

- 提交后无撤回、修改、覆盖或自行重新上传入口；
- 教师要求修改或复测时创建独立新尝试，旧提交不可变；
- 水印为含完整学号的斜向长串文字并铺满页面；
- Excel 可追溯到学生、任务、模板、实验尝试和不可变提交；
- 教师能看到学生填写结果和从文件提取的原始结果；
- 阶段 5 不因自动计算或图表未完成而阻塞验收。
